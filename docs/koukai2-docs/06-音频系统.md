# 06 音频系统

## 6.1 架构

```
MAIN/OPEN/END ──int 66h API──→ FMDRV.COM (TSR)
                                  │  钩 int 8 计时器节拍
                                  │  读 D2.MML 乐曲序列（由主程序载入内存后移交）
                                  └─ out 388h/389h ──→ AdLib (Yamaha OPL2 / YM3812)
```

- **FMDRV.COM**（5 055 B）安装在 **int 66h** 上提供播放 API；重复安装时会通过 `AH=FFh` 握手探测旧实例并先卸载（`int 21h AH=49h` 释放其内存）再重装，退出码区分安装失败原因。
- 音序节拍来自 **int 8**（系统计时器，8253/8254；驱动内有 `out 40h/43h` 对 PIT 重编程的代码，即提高 tick 频率以获得音乐分辨率，并按比例转发原 BIOS tick）。
- OPL2 写入采用标准「写索引→延时→写数据→延时」序列（地址端口 388h 出现 6 处，数据端口 389h 2 处，配套 `in al,dx` 状态等待循环）。

## 6.2 D2.MML —— 乐曲数据（27 866 B）

- 文件头是**小端 u16 偏移表**，按「4 个声道偏移 + 1 个 0 终止符」为一组，每组即一首乐曲：
  `[1122,1224,1455,1496,0] [1598,1868,2090,2303,0] [2382,…]`
  即每曲 **4 个 FM 声道**的独立音序流（OPL2 共 9 声道，游戏音乐用 4 声道编曲，余量留给音效）。
- 偏移指向编译后的 MML（Music Macro Language）字节码：音高/时值/音量/音色切换等命令的紧凑流。MML 是 KOEI/日本 PC 游戏时代的标准音乐中间格式，源码形如 `t150 o4 l8 cdefg…`，此处为其二进制编译产物。
- 估算曲目数：表区约 20+ 组（片头曲、港口、航海、战斗、事件、结局等）。

## 6.3 音色

OPL2 音色（每声道 2 个操作器的 ADSR/倍频/波形参数，约 11 字节一组）应内嵌于 FMDRV.COM 数据区或 D2.MML 的音色段中。

> 说明：`1.PAT / 2.PAT` 虽然扩展名像「patch」，但实为 16×16 1bpp 中文点阵字库（Big5 顺序），与音频无关，见文档 04。
