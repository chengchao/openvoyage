# KAO 对话头像显示链 · 校准笔记（2026-06-10，未竟）

对照实机对话窗截图（若昂，DOSBox-X）逐像素校准 KAO 头像时发现：**48×80 解码数据与实机显示存在
超出「调色板选择」的系统性差异**。调色板 0x47A50（对话表，commit 9e14f42 已采用）渲染的头像
与实机观感接近但不一致。本笔记记录已证实事实与已排除假设，收尾需反汇编/仿真 CC 操作码的画脸例程
（同 GRAPH.DAT 0xFF4 的 _emu8086 方法）。

## 已证实（byte/pixel 级）

- **KAO.LZW 实为 128×1920B + 128×864B 两族 chunk**（此前文档记「256 块头像」不完整）。
  1920B = 48×80 4bpp（布局 A cell 交错，与 pixels.decode_interleaved 一致，鲜活解码与
  assets-converted PNG 100% 相同）；864B 族用途未明（4bpp 可为 48×36 —— 疑口型/眨眼动画补丁）。
- **实机对话头像显示区 = 168×200 屏幕 px**（截图 bbox 边缘锐利、逐行列众数验证），
  对 48×80 原图即 **横 3.5× / 纵 2.5× 非均匀拉伸**——非任何整数 blit 组合；文字字模高度
  （16px 字模 → 实测 ~34px）给出窗口缩放 ≈2.1，与 2.5/3.5 均不符 → 引擎画脸路径存在
  额外变换（疑列复制模式或合成）。
- **区域级（cell 级）索引构成与实机吻合**：bg=idx0+2 暗橙棋盘、cheek=6/7/11、hair=6/13/15 等
  区域平均色与候选调色板部分吻合（hair 区匹配 0x47A50、coat 区匹配 0x4785C —— 无单一已知表全合）。
- **像素级拟合被拒**：以「显示 = pal[解码索引图]」做最小二乘/迭代去溢色（含 2×blit+双线性模型、
  子像素对齐搜索、镜像位序），最优 rms ≈ 54/通道 —— 假设不成立。同一索引（如 idx1）在脸部区
  须为暖色、外套区须为蓝色 → 解码索引图与显示像素的**逐像素对应关系**有系统性错位。

## 已排除（勿重试）

- ❌ 调色板问题单独成因（11 张 MAIN.EXE 表 + KOUKAI2.DAT/OPEN/END 共 43 候选全试，无一逐像素吻合）
- ❌ chunky（按字节双 nibble）、整图平面、行平面、16px 字交错、列主序、双行交错、cell 内位序镜像
- ❌ 80×96 = 两 chunk 拼接（上下半 / 平面对分跨 chunk）→ 全噪声
- ❌ GRAPH.DAT / GRAPH2.DAT 中藏脸（无 48×80 族块；GRAPH2 仅 144×56 + 640×400 两块）
- ❌ assets-converted 头像过期（鲜活解码 100% 一致）
- ❌ IAP（56×88 全身事件立绘，非对话脸）
