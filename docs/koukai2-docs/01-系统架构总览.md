# 01 系统架构总览

## 1. 程序结构：四个程序 + 两个驻留模块

游戏不是单一可执行文件，而是由一个微型启动器串联多个独立程序，用 **DOS 退出码** 作为程序间的控制流信号：

```
KOUKAI2.COM (776 B 启动器，常驻)
   │ 1. EXEC FMDRV.COM   ← FM 音源驱动，TSR 常驻 (int 66h)
   │ 2. EXEC OPEN.EXE    ← 片头动画 / 开场
   │ 3. EXEC MAIN.EXE    ← 游戏主体
   │      ├─ 退出码 0 或 2 → 回到第 2/3 步（返回标题）
   │      └─ 其他退出码    → EXEC END.EXE（结局画面）→ 再回标题
   └─ (内嵌文件名表还包括 PW.EXE，本拷贝中不存在，推测为原版的
      手册查询式防拷贝程序，该流程在本版本中未被调用)
```

启动器反汇编要点（地址为 COM 装载后内存地址）：

- `0x3CC`：`int 21h AX=3565h/2565h` —— 接管 **int 65h**，安装自定义服务中断（见 §2）
- `0x3EE`：`int 10h AX=0012h` —— 设定 **VGA mode 12h（640×480×16 色）**，全游戏唯一的显示模式
- `0x3C0`：接管 int 24h（DOS 严重错误），磁盘出错时直接在图形屏上显示 `DISK ERROR HIT ENTER to RETRY` 并等待回车重试，避免 DOS 默认的 `Abort, Retry, Ignore` 破坏画面
- `0x357`：`int 21h AH=4Ah` 收缩自身内存到约 0x79 段，把常规内存让给子程序

## 2. int 65h：跨程序通信枢纽

KOUKAI2.COM 常驻部分在 int 65h 上提供一组服务（AH 为功能号的跳转表位于驻留段 `0x216`），功能包括：

- 查询启动器数据区段地址（COM 头部 `0x103–0x110` 存有驻留段指针表）
- 在 OPEN/MAIN/END 之间 **传递少量状态**（约 0x15 字的参数块，驻留代码 `0x328` 处有把 BX:CX 指向的 21 字节拷贝进驻留区的例程）——这是「片头→主程序→结局」能衔接剧情选择的机制
- 显示磁盘错误画面（与 int 24h 处理共用例程）
- 查询显示卡状态（保存了启动时 `int 10h AH=0Fh` 的原始显示模式，退出时恢复）

MAIN.EXE 退出前通过 `int 21h AX=4Cxx` 携带退出码，启动器据此决定走结局还是回标题——退出码本身也是一种「跨程序消息」。

## 3. 运行环境与内存布局

| 项 | 值 |
|---|---|
| 操作系统 | MS-DOS 2.0+（入口处 `AH=30h` 检查版本 ≥2） |
| CPU | 8086 实模式，16 位 |
| 显示 | VGA mode 12h，平面显存 A000:0000，行距 0x50（80 字节） |
| 声音 | AdLib (OPL2)，经 FMDRV.COM 的 int 66h API 访问 |
| 鼠标 | 标准 int 33h 驱动（文件名表中含 MOUSE.COM，本拷贝未带） |
| 中文显示 | int 15h AX=5000h 字型服务（BX=0100h, DX=1010h → 16×16 点阵），由倚天/DOS-V 类中文系统提供 |

MAIN.EXE 的 MZ 头：装载映像 277 569 字节 + 至少 16 KB BSS（minalloc 0x400 段），栈 SS:SP = 4444h:3800h（相对段），重定位项多达 **5231 条、6 个段** ——这是大型多段 C 程序的典型特征。

## 4. 整体数据流

```
                 ┌────────────── 启动时一次性 ──────────────┐
KOUKAI2.DAT ──→ 主数据库（游戏初始状态/存档，328 991 B）      │
DATA1.LZW  ──→ 调色板/字体/UI 等杂项资源（19 块）             │
1.PAT 2.PAT──→ 地图图块位图                                  │
                 └─────────────────────────────────────────┘
航海画面:  WORLDMAP.LZW(世界地图) + WINDCUR.DAT(风/海流格网)
港口画面:  PORTMAP.LZW(101 张 96×96 图块地图) + PORTCHIP.LZW(图块)
           + CHIP_NO.DAT(每港使用的图块组编号)
人物对话:  KAO.LZW(256 张人物头像) + NAME.TBL(人名表)
           + SNRn.DAT(剧本脚本) + SNRn.MES(剧本台词)
           + EVENTn.DAT(事件资料, 每主角一份 n=0..6)
界面文本:  MESSAGE.DAT(1022 条系统讯息) + MENU.DAT(61 条菜单文本)
           + ITEM.MES(物品名/说明)
战斗:      CHAR.LZW(战斗单位图) + MONSTER.DAT(海怪数据)
音乐:      D2.MML(乐曲序列) → FMDRV.COM → OPL2
结局:      END.EXE + ENDGRP.DAT(结局图档) + END_PUT.DAT/HDAT.PUT(贴图指令表)
片头:      OPEN.EXE + OPGRAPH.LZW(14 幅全屏图)
```

## 5. 工程层面的设计特点

1. **磁盘空间极限压榨**：所有大体积图档均经 LS10/LS11 熵压缩（详见文档 03），字典按字节频率排序使常用字节只需 2 bit。
2. **程序拆分以适配 640 KB 常规内存**：片头、主体、结局拆成三个进程串行执行，互不挤占内存；驻留部分（启动器 + 音源驱动）合计仅约 7 KB。
3. **数据驱动设计**：剧本（SNR）、事件（EVENT）、菜单、讯息全部外置为带偏移表的数据档，主程序是解释器——7 位主角共用同一套引擎，仅靠数据档区分。
4. **C + 汇编分层**：业务逻辑用 Microsoft C；图形 blit、解压热路径、中断处理是手写汇编（OPEN/MAIN/END 三个 EXE 里链接了同一套汇编图形库，二进制级雷同）。
