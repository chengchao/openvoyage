# 03 LS10 / LS11 压缩格式（已验证）

KOEI 专有的「带频率字典的 LZSS + 指数哥伦布变长码」容器格式。游戏内所有 `.LZW` 文件使用它（注意：与标准 LZW 算法无关，扩展名是误导）。`LS10` 与 `LS11` 容器结构与编码完全相同（本游戏数据上互相可解），仅版本标识不同。

**验证方式**：按下述规格实现了独立解压器（`tools/ls11_extract.py`），对游戏内全部 LZW 容器（WORLDMAP、CHAR、DATA1、IAP1–6、IAE1、KAO、PORTCHIP、PORTMAP、OPGRAPH）逐块解压，输出字节数与头部声明的原始大小 **全部精确一致**，且图像数据渲染正确。

## 3.1 容器布局

| 偏移 | 大小 | 内容 |
|---|---|---|
| 0x000 | 16 | 魔数 `"LS11"` 或 `"LS10"`，余者补 0 |
| 0x010 | 256 | **字节字典**：256 个字节值按出现频率从高到低排列 |
| 0x110 | 12×n + 4 | **条目表**：每条 12 字节（3 个大端 u32）：`压缩大小, 原始大小, 文件内绝对偏移`；以 4 字节 0 终止 |
| 表后 | — | 各条目的压缩位流（条目偏移字段直接指向这里） |

条目偏移自洽性：`条目[i+1].偏移 = 条目[i].偏移 + 条目[i].压缩大小`（已在多个文件上验证）。

## 3.2 位流编码

位流按字节顺序、**每字节自高位到低位**读取。基本单元是一个变长非负整数 code，采用类指数哥伦布（Exp-Golomb）编码：

```
读取连续的 1 比特，计个数 k（遇到 0 停止，0 也被消耗）
base = 2^(k+1) - 2
再读 k+1 个比特作为二进制数 w
code = base + w
```

即：code 取值区间按前缀长度分层：`0xx→0..1`，`10xxx→2..5`，`110xxxx→6..13`，…

解码主循环：

```
while 输出长度 < 原始大小:
    c = getcode()
    if c < 0x100:                 # 字面量
        输出 dictionary[c]        # 经频率字典转换！
    else:                         # 回溯拷贝 (LZSS)
        length  = getcode() + 3
        distance = c - 0x100      # 从当前位置向回 distance 字节
        逐字节复制 length 个（允许源区间与目标重叠，即 RLE 效果）
```

## 3.3 设计巧思

1. **频率字典 + 变长码的组合**等价于一个静态熵编码器：最常见的字节值 code=0/1，只占 2 bit；与 LZSS 回溯压缩叠加，对图块类数据压缩率非常好（如 PORTCHIP.LZW 实测约 3.4:1）。
2. 字面量与匹配距离共用同一个变长码空间（<256 为字面量，≥256 为距离+256），省掉了类型标志位。
3. 分块（条目）设计允许随机访问单个资源（如只解第 37 号头像），不必解整个文件——配合 12 字节条目表里的绝对偏移可直接 `lseek`。

## 3.4 对应的游戏反汇编位置

算法从 OPEN.EXE 反汇编恢复（MAIN/END 内含同款代码）：

- getcode 位流例程：OPEN.EXE 映像偏移 `0x26C4`（位缓冲字节存于 DS:[0xEBE]，剩余位数 DS:[0xEE2]）
- 解压主循环：`0x89C9`（`cmp di,100h` 判字面量/匹配；`0x8A21` 处 `mov al,[bx+di]` 即查频率字典）
- 容器条目定位：`0x8A4F`（`mul 0Ch; add ax,110h` —— 12 字节条目、表基 0x110 的直接证据）
