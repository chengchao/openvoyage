# 04 图形系统

## 4.1 显示模式与显存

全程使用 **VGA mode 12h：640×480、16 色、4 个位平面**（启动器设置，`int 10h AX=0012h`）。显存 `A000:0000`，每行 80 字节（0x50），每字节 8 像素，颜色由 4 个平面上同位比特拼成 4 位索引。

写屏经由 VGA Sequencer `3C4h` 的 Map Mask（reg 2）逐平面选通 + `movsb`；蒙版精灵用 `AND` 清孔 + `OR` 填色两遍合成；Graphics Controller `3CEh` 用于设置写模式、位旋转和位蒙版（见文档 02 §2.5 反汇编）。

## 4.2 位图存储格式（已验证）

所有位图资源使用统一的「**8 像素单元、4 平面交错**」布局，与 blit 例程的读取顺序一致：

```
对每个扫描行、每个 8 像素单元：
  字节0 = 平面0（颜色位0）的 8 个像素
  字节1 = 平面1   字节2 = 平面2   字节3 = 平面3
即每 4 字节 = 8 个像素，行大小 = 宽/8×4 字节
```

验证：按此格式渲染 KAO.LZW 的头像块得到清晰人脸（0x47A50 对话调色板着色，六位主角与实机一致；渲染图是原版美术，不入库）。

**例外——16×16 地图图块（PORTCHIP.LZW、推测含 1.PAT/2.PAT）使用平面顺序布局**：每图块 128 字节 = 平面 0 的 32 字节（16 行 × 2 字节）+ 平面 1、2、3 各 32 字节。已实证渲染出海岸线、城墙、屋顶与设施招牌图块。两种布局对应汇编库里两条不同的 blit 路径。

**调色板**（已精确定位，按用途分表，嵌在 MAIN.EXE 数据段，48 字节 (B,R,G) nibble 格式，见 `converter/koukai2/palette.py`）：

- **港口白天基表 @ 0x45F86**（映像偏移 0x40D86）：idx0–14 已对里斯本截图逐像素验证（KOUKAI2.DAT 0x1009D 有随存档运行时副本）；0x45FB6 为夜晚/暗化变体。GRAPH.DAT 店主画用它渲染（店主画不含 idx15，与显示表无差异）。
- **港口显示表 @ 0x4785C**（映像偏移 0x4265C）：**PORTCHIP 图块与 CHAR 行走精灵用它**。与 0x45F86 仅差 idx15：紫 (97,32,195) → 米白 (243,227,211)（=idx7 同值）。2026-06-10 实机裁决（里斯本白天 DOSBox-X 截图逐像素普查）：紫全画面 **0 像素**、米白 21.4 万像素，而 PORTCHIP 每组 157–204/240 个图块含 idx15（里斯本在用 219 块中 176 块——道路亮部/窗框/墙面），故显示态 idx15 必为米白；0x45F86 的紫为非显示态（基表/调色动画用，归属待考）。同一截图亦钉死精灵 idx3=腮红粉 (211,97,162)（行走 NPC 脸颊成簇实测）、idx4=绿 (0,162,97) 在场，而旧反推表猜测值 暗红/暗棕/乳白 全画面 0 像素。PORTCHIP 图块不含 idx2/3/4（全 7 组实测），CHAR 精灵只用 idx0–7。
- **对话/头像表 @ 0x47A50**（映像偏移 0x42850）：**KAO 头像与 IAP 事件立绘用它**，含完整肤色阶梯（idx 8/9/11/12/13/15 肤/棕褐、10/14 深棕、6 金黄）。2026-06-10 实证：kao_000–005 六位主角逐一目验（若昂金发、奥特罗胡须、肤色自然）与实机一致；IAP 用港口表渲染则头发发白、肤色发灰（iap1 块 5/20 双表对比），且事件立绘与头像在对话场景同屏、必共用一张 DAC 表。
- MAIN.EXE 内共扫到 11 张候选 16 色表（首色黑、全 nibble、≥10 distinct）：0x45F86 / 0x45FB6 / 0x46FC6 / 0x475FB / 0x477F9 / 0x4782C / 0x4785C / 0x4788C / 0x478BC / 0x47A50 / 0x47A80，其余归属待考（按场景切换：战斗/航海/室内等）。
- 历史注记：早期曾用里斯本参考图反推的单一「港口反推表」（`pixels.GAME_PALETTE`，idx 2/3/4 为猜测值）渲染一切位图——先是 KAO/IAP 人脸大片蓝绿紫（2026-06-10 上午改用 0x47A50 对话表），随后港图截图裁决 idx15（同日下午）后 PORTCHIP/CHAR 也改用 0x4785C 显示表、反推表整表删除。所有渲染路径现一律从 MAIN.EXE 取表，金值钉在 `converter/tests/test_palette.py`。

游戏画面大量使用 2×2 抖动（dithering）模拟中间色——16 色下表现海洋渐变/肤色过渡的经典手法。

## 4.4 港口画面的三层结构

```
CHIP_NO.DAT (100 B)         每个港口一字节：使用哪一组图块(0..6)
        │
PORTCHIP.LZW 第 n 组 ───→  16×16 图块位图集（按文化圈分组：
        │                   欧洲/伊斯兰/非洲/印度/东亚…）
PORTMAP.LZW 第 p 块 ───→   96×96 图块索引 → 拼出 1536×1536 像素的港口
```

这是经典的 tile-map 设计：101 个港口只需 7 套图块 + 每港 9 KB 索引，总开销 <300 KB。

> **主角的半格网格**（实证）：行走主角并**不**与 16px 图块网格对齐，而是**右移半格(8px)**——
> 主角立于两格之间（中心落在图块边界），故能正对**2 格宽的门**（门 = 入口坐标 ZA_DAT 处的左框 +
> 右侧开口，招牌在 +2）居中站立。这正是 CHAR.LZW 存「8px 预移位副本 / 双字节列」的用途：
> 引擎要在半格(byte)位置贴图。复刻里若让主角与图块同格，就会偏到门左侧（已修：`CHAR_X_SHIFT`）。

## 4.5 WORLDMAP.LZW 世界地图格式（已破解，2026-07-11）

**总体**：世界地图为 **1080×540 图块**（16×16 px/块 ⇒ 全图 17 280×8 640 px；陆地占比 26.5%≈地球实况）。
LS11 容器内 3 块 = 3 条**纵向条带**：x∈[0,360)、[360,720)、[720,1080)。每条带 = **30×45 = 1 350 个
12×12 图块的 chunk**，chunk 按行主序编号（chunk i → 带内列 i%30、行 i/30）。地图西起大西洋中部
（亚速尔以西），欧非居左、美洲居右（航海东西向回绕）。

**条带内格式**（三块同构）：

```
0x000   u16le × 1350   chunk 偏移表（相对数据区起点 0xA8C；注意与 LS11 头的大端不同，这里是小端）
0xA8C   chunk 数据区

单个 chunk：
  头字节 H
  H & 0x80 ≠ 0 → 整个 chunk 均一填充图块 (H & 0x7F)，chunk 仅此 1 字节（大洋近乎免费）
  否则         → 18 字节位掩码（144 位，字节内 MSB-first，按 12×12 行主序展开）
                 + N 个显式图块字节（N = 掩码置位数）
                 位=0 处填 H，位=1 处依次取显式字节
```

两级结构（偏移表 + 定长 12×12 chunk）使引擎卷动时可随机寻址可视窗口的 chunk，无需整图驻留。

**验证方式**（2026-07-11，逆向脚本时值）：① 结构自洽——三块共 4 050 个 chunk 全量解码，
`len = 1 + 18 + popcount(掩码)` 对全部非均一 chunk 成立，三块数据区 22 694/19 273/21 207 B
**零残差吃尽**；② 地理对照——按上述编排渲染 1080×540 索引图，大陆轮廓/水系（尼罗、亚马逊、
西伯利亚诸河）/山脉（安第斯、阿特拉斯、扎格罗斯）/两极与真实地理逐一可辨；位掩码若非 MSB-first
或 chunk 若非 12×12，海岸线即碎为噪声，图形本身即是证明。

**图块值语义（初勘，供 M6 地形类别与可航判定讨论）**——全图 583 200 格直方图 + 地理对照：

| 值域 | 频次 | 判读 |
|---|---|---|
| 0x7D (125) | 358 197 (61.4%) | 大洋/深海（均一 chunk 主填充） |
| 0x7C (124) | 154 551 (26.5%) | 平原陆地填充；**两极冰盖也用它**（顶部整行均一 0x7C）＝不可航 |
| 0x78–0x7B (120–123) | 34 663 | 近岸/浅海变体（沿岸成带；地中海边缘、波罗的海/红海内部大片） |
| 0x00–0x0F | ≈30 000 | 海岸线块（0x0F 最常见=通用岸线，其余为走向/形状变体），亦构成河流线 |
| 0x10–0x5F | ≈8 000 | 陆上细节：河流、森林、丘陵、沙漠、地标（0x20 较多） |
| 0x60–0x77 | 少量 | 山脊线（阿特拉斯/托罗斯/扎格罗斯/安第斯逐条对位） |
| 0xAC–0xB6（0xAF 占 1 056 格） | ≈1 300 | **礁石/浅滩散点**：撒在近岸可航水域，红海/爱琴海/波斯湾/大堡礁密集——航海危险地形 |
| 其余 ≥0x80 | 零星 | 特殊块待考（如 0x81×44） |

可航判定假说：0x7D、0x78–0x7B 可航；0xAC–0xB6 可航但触礁风险；其余不可航。
逐值精确表需 MAIN.EXE 内 256 项分类 LUT（航海碰撞必有查表）或实机逐类探测钉死。

**图块集（tileset）线索**：DATA1.LZW **块 11**（32 768 B = 256 块 × 128 B，16×16 平面布局同
PORTCHIP）上半部实绘海岸/沙滩/雪峰/森林等地形块；中段一批块**画着自身十六进制编号**（0x54–0x60
等）＝运行时替换槽（疑为海面动画帧）；但地图字节与该表**非直接下标**（0x7C/0x7D 在表中是村落/
房屋块）——存在偏移或引擎间接表，待逆向；块 11 下半部非图块内容。航海画面所用 DAC 调色板
在 §4.2 的 11 张候选表中亦待归属。

**与 PORTCHIP/PORTMAP 体系对比**：同为 16×16 图块 tile-map，差异——
① PORTMAP 是每港 96×96 裸索引矩阵（整块驻留），WORLDMAP 是「偏移表 + 位掩码 chunk」两级
随机寻址（1080×540 大图的卷动/空间优化，48 KB 容器装下 58 万格）；
② PORTCHIP 按文化圈 7 组整组常驻，世界图块集单套（DATA1 块 11 嫌疑）+ 运行时动画槽；
③ 均一 chunk 1 字节的设计只有世界图有（大洋压缩比极高）。

**未决**（已挂回 Wayfinder 地图）：① 地图字节→图块集索引的映射与动画槽机制；② 逐值可航/危险
LUT；③ WINDCUR.DAT（1 350 B）与「每条带 1 350 chunk」数字巧合是否有含义（或为 45×30 / 90×15
世界风格网），归 M6；④ 港口世界坐标表不在 COLONY.DAT 直存（u16 图块坐标 / u8 度数两种编码已
排除），位置另寻（COLONY/TRANSIT 票）。

## 4.6 文字渲染

- 中文：通过 `int 15h AX=5000h`（BX=0100h、DX=1010h）从中文 DOS 系统获取 16×16 字型例程指针，远调用逐字取字模后用平面 blit 上屏。这意味着 **游戏必须运行在倚天等中文系统环境下才能显示中文**。
- 数字/拉丁字母与小字号 UI：游戏自带点阵字（嵌于 DATA1.LZW / 可执行文件数据段）。
- 文本编码是自定义双字节码（详见文档 07 §7.5）。
