# 07 游戏内容与设计数据

本篇从数据档反推游戏的内容组织——即「设计层」的架构。

## 7.1 七个剧本容器 = 一套引擎、多位主角

《大航海时代 II》的标志性设计是 6 位可操作主角共用同一张世界地图与经济系统，剧情互相穿插。六位主角按 SNR1–6 / KAO 0–5 / IAP1–6 的统一次序为：**若昂（葡，探险）、卡塔莉娜（西，复仇海战）、奥特罗（英，私掠）、恩斯特·洛佩斯（尼德兰，地理学家/绘世界地图）、皮埃特罗·康迪（意，寻宝）、阿兰·维斯特（奥斯曼，商人）**。

> **2026-06-10 勘误**：此处旧名单「伊尔·哈米德、李华梅」有误——全部已解码游戏文本（MESSAGE/MENU/SNR0–6.MES）中两名零命中；实据为 snr1 #1002、snr4 主角自述、snr6 主角自述及其在 snr1/5、snr6 的客串台词（原文不入库，可由本地转换产物复查）；母港 snr4=33（北海）/snr5=8（地中海）/snr6=2（东地中海）与国籍吻合；kao_003 金发长发眼镜=恩斯特、kao_004 乱发束带=皮埃特罗、kao_005 缠头巾=阿兰（4× 放大目验）。

数据层的对应物：

- **SNR0–6**：7 套剧本容器。SNR0（编号字段 0x0080，与其余 0x0000–0x0005 不同）是共通/序章部分；SNR1–6 对应六位主角。
- 每套 = `SNRn.DAT`（魔数 `SNDT`，BE32 偏移表指向若干**脚本分节**，0xFFFFFFFF 终止）+ `SNRn.MES`（台词文本，BE32 偏移表）。
- 台词量对比（条数）：SNR1=1176 > SNR6=926 > … > SNR0=192 —— 主线剧本（若昂线）文本量最大，与玩家体感一致。
- **EVENT0–6.DAT**：与剧本平行的事件资料档，与 SNR 同样按「共通 + 六主角」分 7 档，内部按章节分 2–6 个大块（BE32 偏移表，条目带 0xC0 标志位）。
- **IAP1–6.LZW**：六位主角各自的剧情事件立绘（35 块 = 7 场景 × 5；曾误判为文化圈设施店员，2026-06-07 实机裁决更正，详见文档 08 §8.3 与文档 04 §4.3）。

主程序 MAIN.EXE 因而是一个**剧本解释器**：读 SNR 脚本字节码 → 触发事件 → 查 MES 表显示台词 → 用 KAO.LZW 第 n 块显示头像。

## 7.3 港口经济与界面

ITEM.MES（物品名/说明，`\n\0` 分隔）+ MENU.DAT（61 组菜单）+ MESSAGE.DAT（1022 条系统讯息）构成交易/造船/酒馆等全部 UI 文本。文本与代码完全分离，是为多语言移植（日→中）准备的典型结构——中文化只需替换这些数据档与字型，不动主程序逻辑。

## 7.4 结局系统

END.EXE + ENDGRP.DAT（60+ 图块，399 KB）+ END_PUT.DAT/HDAT.PUT（8 字节一条的贴图指令数组）。MAIN.EXE 以**退出码**告知启动器进入结局；结局画面按主角与达成度组合播放（指令表驱动的幻灯片引擎）。

## 7.5 文本编码（部分为假说）

文本（NAME.TBL、ITEM.MES、COLONY.DAT、*.MES）使用**自定义双字节编码**：

- 首字节范围近似 Shift-JIS（0x81–0x9F）但额外扩展了 0xA0–0xAE 段（标准 SJIS 中该段是半角片假名，不可作首字节）；
- 按 Shift-JIS/Big5/GBK 直接解码均不产生有效文句 → 码位是**字型档的字模索引**而非标准字符集；
- **自带字库已找到：1.PAT / 2.PAT**（16×16 1bpp 点阵，每字模 32 B；1.PAT 5409 模 + 2.PAT 6800 模，合计 12209，见文档 04）。文本码值即字库字模索引。

### 编码结构（2026-06-07 破解）

文本码为双字节 `(hi, lo)`，`hi ∈ 0x81–0xD7`，`lo` 取自 **4 段可打印区间** `0x30–0x39 / 0x41–0x5A / 0x61–0x7A / 0x80–0xFD`，每段去掉控制/分隔字符后**恰好 188 个有效值**（与 ETen/倚天 自定义字库的打包方式一致）。控制码：`0x00` 终止、`0x0A` 换行、`0x24 xx` 变量。

- **标点已实证解码**：`lead 0x81` = 符号行，`字模 = rank(lo)`。已渲染验证：`0x8131=，`、`0x8134=。`、`0x8138=？`、`0x8139=！`（出现频次也最高，4130/2582/902/834 次，符合标点统计）。
- **汉字骨架**：`字模 ≈ (hi-0x81)·188 + rank(lo)`，`rank(lo)` = lo 在上述 188 值中的序号。此式让符号行与整体结构（逗号/句号落点）完全对位，但**汉字部分有累积错位**——按此式渲染出的是清晰但不正确的汉字（stride 184–195 扫描均不命中 的/是/我 等高频字）。
- **字库排序已查明：部首/笔画序，非 Big5 码序**（实证渲染 1.PAT：glyph 0–407 为符号/数字/罗马/希腊/拉丁；之后是「一丁二十…又口土士女子寸小」即**康熙部首顺序**）。因此任何「码值→Big5→字模」或「(hi-0x81)·W+rank(lo)」公式都对不上汉字——符号行（lead 0x81）能对上纯属因为符号本就在字库最前。
- **已排除**：文本码按 Big5 / GBK / GB18030 / SJIS 直接解码（全部乱码）；字库按 Big5 码序（部首序证伪）；密排子集（2793 个码 ≪ 12209 字模）；单调的「每 lead 基址表」（MAIN.EXE 数据段未扫到）。
### 反汇编结论：汉字字形来自**外部中文系统**（int 15h），非游戏文件

沿文本绘制链反汇编（MAIN.EXE），得到决定性结论：

1. **取字模走 int 15h AX=5000h**（asm 库 0x238/0x268，`BH=1, DX=1010h` = 16×16 中文字模服务）。该服务由**外部中文系统 TSR**（倚天/DOS-V 类，DOSBox-X 内置提供）实现——**没有任何游戏可执行档 hook int 15h**（查 `AX=2515h` 全为空），即字模 ROM 不在游戏文件里。
2. **码转换算式已定位：MAIN.EXE 0x43A1**。它把 MES 的 2 字节内码 `(hi, lo)` 变换成中文系统的字模码：
   ```
   if not (0x80 < hi < 0xF0): 非汉字
   h = ((hi - (0x70 if hi<0xA0 else 0xB0)) << 1) & 0xFF
   l = lo - (1 if lo>=0x80 else 0)
   if l < 0x9E:  h -= 1
   else:         l -= 0x5E
   字模码 = (h << 8) + (l - 0x1F)
   ```
   实测 `(0x97,0xFA)→20092`、`(0x81,0x31)→0x2112`。**输出 > 12209**（1.PAT/2.PAT 字模总数），故**这不是 1.PAT/2.PAT 的索引**——1.PAT/2.PAT 是游戏自带的另一套字库（半角/符号/标题用，部首序），与 in-game 汉字无关。另有一条 0x4470 处理「半角+全角混排」文本（第二字节 0x21–0x7C 选择子），与 MES 路径不同。
3. **像素级实证（决定性，2026-06-07）**：从实机截图干净采样出在屏汉字 `里斯本港`（4 个 16×16 字模，渲染确认无误），对 **1.PAT/2.PAT 全部 12209 个字模**做**容错（±2px 平移）汉明距离**搜索——最佳距离 **13–45/256**（同字库真匹配应 ≤5；距离 13 那个经渲染核对是**另一个字**，属近似巧合）。即**在屏字模不在 1.PAT/2.PAT 内**。结合「无游戏档 hook int 15h」，**坐实：in-game 汉字字形来自外部中文系统（int 15h AX=5000h），非 1.PAT/2.PAT**。1.PAT/2.PAT 是游戏自带的**另一套字库**（部首序、不同字形），用作 OPEN/标题或无中文系统时的回退，**不是 in-game 显示字体**。
4. **因此：纯靠游戏文件 + 反汇编无法把汉字还原成 Unicode**——最终字形在外部中文系统的字模 ROM 里。已拿到的是「内码→中文系统字模码」的精确算式（`to_font_code()`）。

**已排除（勿再尝试）**：
- ❌ OCR 1.PAT/2.PAT 来认 in-game 字 —— **字库不对**（在屏字模不在其中，像素实证）。
- ❌ 文本码按 Big5/GBK/GB18030/SJIS 直接解；❌ 1.PAT/2.PAT 按 Big5 码序（实为部首序）；❌ `(hi-0x81)·188+rank(lo)` 直接索引；❌ 密排子集。

**真正收尾路径**（需外部信息，非游戏文件内）：取 **DOSBox-X 实际渲染本游戏所用的中文字库**（其内置 CJK 字体资源），把 `to_font_code()` 输出映射到该字库取 16×16 字模 →（OCR 或该字库自带码表）得 `字模码→Unicode`，套表批量解码全部 5000+ 台词。或直接对**实机截图**逐句采样后让 Claude 视觉转写（采样脚本已验证可行）。建议在 Claude Code（真机有 DOSBox-X 字库）里收尾。
